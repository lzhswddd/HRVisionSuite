# FlowDemo 生成流程代码说明

本文档说明 FlowDemo 的**流程代码**从「生成 → 装配 → 执行」的完整链路。
流程代码 = 流程拓扑（`.ndjs`）+ 节点代码（`Flow/*/*.py`）+ 运行时配置（`pipeline.json`）。
架构总览见 [README.md](README.md)，这里只讲代码是怎么来的、怎么跑的、怎么改。

## 1. 链路总览

```
① 拓扑生成                ② 节点业务代码            ③ 启动装配               ④ 运行时拓扑
编辑器导出 .ndjs      Flow/camera|algo|main/     HRStar.py            pipeline.json / SpecBuilder
  └─ main.ndjs          ├─ ThreadGlobalData.py    └─ HRFlowController      └─ PipelineManager
  └─ camera.ndjs        ├─ 开始_*.py                   .main()                   ├─ 节点实例（thData 注入参数）
  └─ algo.ndjs          └─ 抓帧/等帧/…节点 .py          ├─ 解密 .ndjs 流程图        ├─ 通道（queue→DataBus / shm→DisplaySlot）
  └─ videos/ccd*.avi                                    ├─ 逐节点执行节点代码       └─ 窗格（UI 显示绑定）
                                                         └─ 线程/进程执行器
```

- **① 流程骨架**：`.ndjs` 由可视化编辑器导出（三个流程的节点图），随仓库提交，运行时直接使用。
- **② 节点血肉**：每个节点一个 `.py` 文件，只写本节点的业务（框架按图找到文件并执行）。
- **③ 框架装配**：`HRStar.py` 一行启动框架 `main()`，框架解密 `.ndjs` 重建流程图，按边驱动节点代码。
- **④ 运行时拓扑**：`pipeline.json`（或 SpecBuilder 代码）声明哪些流程节点实例化、怎么联通、显示在哪个窗格——`PipelineManager` 据此生成通道与注入参数。

## 2. ① 拓扑生成：编辑器导出 .ndjs

### 2.1 产物与加密格式

产物：`Flow/main.ndjs`、`Flow/camera.ndjs`、`Flow/algo.ndjs` + `Flow/videos/ccd1..8.avi`（模拟视频流）。
`.ndjs` 与视频已随仓库提交（.gitignore 不含它们），克隆即可运行，无需生成。

`.ndjs` 是编辑器流程图的导出格式，AES-CBC 双层 base64 加密：

```
明文 JSON ──AES-CBC(KEY)──▶ base64(iv)||base64(密文) ──外层 base64──▶ .ndjs 文件
```

框架侧 `_Controller.read_and_decode_file()` 逆过程解密，还原成流程图 JSON：

```json
[{
  "flowID": "camera", "parentID": "main",
  "nodes": [
    {"id": "c1", "type": "StartNode", "position": {...},
     "data": {"title": "开始", "content": "", "isRunning": true,
              "isSubthread": false, "isNormal": false, "isSwapped": false}},
    {"id": "c2", "type": "ProcessNode", ...},
    {"id": "c4", "type": "OverNode", ...}
  ],
  "edges": [
    {"source": "c1", "sourceHandle": "1", "target": "c2", "targetHandle": "1", ...},
    {"source": "c3", "sourceHandle": "1", "target": "c2", "targetHandle": "1", ...},  // 回边=循环
    {"source": "c3", "sourceHandle": "2", "target": "c4", "targetHandle": "1", ...}   // 另一出口=结束
  ]
}]
```

### 2.2 节点类型与图结构

| 类型 | 含义 | 本项目用法 |
|---|---|---|
| `StartNode` | 流程入口 | 开始节点（无代码逻辑，直接进下一个） |
| `ProcessNode` | 业务节点 | 每个节点对应 `Flow/<流程>/<标题>.py` 一个文件 |
| `OverNode` | 流程出口 | 结束节点 |

三个流程的图：

```
main  （串行，1 个实例）:   m1 开始 → m2 启动进程 → m3 创建UI → m4 结束
camera（循环，每相机 1 实例）: c1 开始 → c2 抓帧 → c3 退出检查 ──c3.1→ c2（回边循环）
                                                            └─c3.2→ c4 结束
algo  （循环，每算法 1 实例）: a1 开始 → a2 等帧处理 → a3 透传 ──a3.1→ a2（回边循环）
                                                            └─a2.2→ a4 结束
```

**回边（edge 指回前面的节点）= 循环**；节点带多个出边 + 不同 `sourceHandle` = 条件分支（handle 是端口号，节点代码里可用）。

### 2.3 拓扑怎么改

在**可视化编辑器**里修改流程图（增/删/连节点）→ 导出 `.ndjs` 覆盖 `Flow/*.ndjs` → 为新节点建对应 `.py`（见 §3）→ 重启生效。
（曾用脚本批量生成演示拓扑，已移除；如需脚本生成可自行按 AES 格式编写，见 §2.1。）

**文件名硬规则**：框架按 `Flow/<流程>/<标题>_<节点id>.py` 定位节点代码
（`data['title'] + "_" + node['id'] + ".py"`）。例：标题「抓帧」+ id `c2` → `Flow/camera/抓帧_c2.py`。
改标题/改 id 时文件名必须同步改。

## 3. ② 节点代码约定

### 3.1 结构骨架

每节点一个文件，例如 [Flow/camera/抓帧_c2.py](Flow/camera/抓帧_c2.py)：

```python
# -*- coding: utf-8 -*-
"""抓帧：取帧 → 推送到 out 通道（队列每帧 / 映射降频）。"""
from camera.ThreadGlobalData import *                  # ① 本流程实例数据（必写）
from services.camera_driver import CameraDriver        # ② 业务封装（放 services/）
from HRVision.HRFlowController import _ChannelOut      #    框架类型（IDE 提示用）

if thData.camera is None:                              # ③ 业务体（可任意长）
    thData.camera = CameraDriver([thData.source])
frame = thData.camera.grab()
if frame is None:
    raise Exception("return", 0)                       # ④ 跳转：回抓帧重试
thData.channel_out.put(frame)                          #    队列通道：每帧发送
thData.channel_out.write(frame, throttle=thData.display_divisor)  # 映射通道：降频写
raise Exception("return", 0)                           # ⑤ 结束本节点 → 框架走下一条边
```

### 3.2 三条硬约定

1. **第一行** `from <流程名>.ThreadGlobalData import *` —— 拿到 `thData`（本实例数据）与 `gData`（全局）与 `signal_instance`（信号）。
2. **结束行** `raise Exception("return", 0)` —— 框架捕获后按当前节点的出边跳转。**不写 = 流程卡死**。
3. **节点文件只在被图驱动时执行** —— 骨架/占位节点可以只写两行（导入 + return），如 [开始_c1.py](Flow/camera/开始_c1.py)。

### 3.3 节点能拿到什么

| 名称 | 来源 | 作用 |
|---|---|---|
| `thData` | 本流程 `ThreadGlobalData.py`（见 §4） | 实例数据：参数 + 框架注入的通道/计数 |
| `gData` | `ProgramGlobalData.py` | 全局数据（`gData.user` 业务配置、`gData.exit_flag`） |
| `signal_instance` | `ProgramGlobalData.py` | 业务信号容器（小数据走 relay） |
| `channel_in` / `channel_out` | 框架注入（聚合通道） | `get` 取输入 / `put`+`write(throttle)` 推输出 |
| `frame_event` 等 | `ThreadDataBase` 基类 | 流程同步事件 |

## 4. ThreadGlobalData：流程实例数据

每个流程一个 [ThreadGlobalData.py](Flow/camera/ThreadGlobalData.py)，**全字段类型注解**：

```python
class ThreadData(ThreadDataBase):
    source: str | None           # 视频源（pipeline_spec 节点参数注入）
    camera: CameraDriver | None  # 相机驱动（缓存，进程存活期）
    cam_str: str                 # 节点 id（打印标识）
    frame_interval: float        # 帧间隔秒（0=不限速）
    display_divisor: int         # 显示通道降频（每 N 帧写一次映射）
    channel_out: _ChannelOut     # 聚合写通道（框架注入）
    loop_count: int              # 抓帧计数

thData = ThreadData()            # 模块级单例：本流程实例共享
```

- **注入时机**：`PipelineManager.start()` 读 `pipeline_spec.nodes[]` 参数，`kwargs` 写入实例的 `thData`（如 `grabber_1` → `source="videos/ccd1.avi"`）；通道对象、显示槽等在通道生成后也注入。
- 节点代码只读写 `thData`/`gData`，**不 import 其他流程的 ThreadGlobalData**（进程隔离）。

## 5. ③ 启动装配：HRStar.py → 框架 main

[HRStar.py](HRStar.py) 只有框架流程代码（约 10 行）：

```python
sys.argv = [path, '--flow', 'Flow', '--main', 'main']   # 指向 Flow/ 目录 + 主流程名
from HRVision.HRFlowController import main
main()
```

框架内部（pyd）执行链：

```
main() → build_processes('Flow', 'main', ...)
   ├─ 读取/解密 main.ndjs → _Process('main') 图
   ├─ 按 node.data.title 定位节点代码文件 → 生成每个节点的 code 可执行体
   ├─ 主流程 m1→m2→m3→m4 逐节点 _Node.run(...)
   ├─ m2 启动进程 → ProcessStartor/ThreadStartor 按 run_mode 启动 camera/algo 流程实例
   │     （camera/algo 的 .ndjs 由 build_processes 一并解密装配）
   └─ m4 结束 → 回收执行器
```

- **每个流程实例**：`ThreadStartor`（线程模式）或 `ProcessStartor`（进程模式，spawn 子进程）。
- **节点执行**：框架 exec 节点 `.py` 源码（`exec(code, _globals, _locals)`），`raise Exception("return", 0)` 即被框架捕获、按出边走到下一节点。
- 进程模式下子进程**重新走 HRStar.py**（`__mp_main__` 再次 `main()`），只装配自己那个流程。

## 6. ④ 运行时拓扑：pipeline_spec → PipelineManager

`.ndjs` 只定义了**流程模板**（camera 流程长什么样），谁跑哪个流程、连什么通道、显示在哪，由 [pipeline.json](Flow/pipeline.json) 二次声明：

```json
{
  "run_mode": "process",
  "nodes": [
    {"id": "grabber_1", "flow": "camera", "source": "videos/ccd1.avi"},
    {"id": "algo_1",    "flow": "algo",   "algo_load": 1, "signal_divisor": 2}
  ],
  "channels": [
    {"id": "ch_grabber_1_algo_1", "from": "grabber_1", "to": "algo_1",
     "kind": "queue", "maxlen": 1, "overflow": "drop_oldest"},
    {"id": "ch_grabber_1_origin", "from": "grabber_1", "to": "ui",
     "kind": "shm", "slot": "origin"},
    {"id": "ch_algo_1_res", "from": "algo_1", "to": "ui",
     "kind": "shm", "slot": "res"}
  ],
  "panes": [
    {"id": "pane_algo_1", "origin": "ch_grabber_1_origin",
     "res": "ch_algo_1_res", "node": "algo_1"}
  ]
}
```

`PipelineManager.start()` 的生成动作：

| spec 段 | 生成物 | 注入到 |
|---|---|---|
| `nodes` | 流程实例（执行器） | 节点参数 → `thData` 属性（source/algo_load/…） |
| `channels` `kind=queue` | `DataBus` 帧队列（maxlen/overflow） | `channel_in`/`channel_out` |
| `channels` `kind=shm` | `DisplaySlot` 显示槽（origin 按相机共享 / res 每算法一段） | 写端节点 `channel_out`、读端 UI |
| `panes` | UI 窗格（origin/res 组合 + 结果信号路由 `pane_nodes`） | `gData.user.windows/display_slots` |

**改拓扑两种方式**（二选一）：
- 编辑 `Flow/pipeline.json` 后重启（`ProgramGlobalData` 启动时加载）；
- 代码里 `PipelineSpecBuilder` 单步配置 → `build()` → `PipelineManager(gData, signal_instance, spec, gData.user)`。

> `make_pipeline_spec()` / `export_pipeline_spec()` 可一键生成默认配置并导出成 JSON 再手工改。

## 7. 修改流程代码的完整工作流

| 想改什么 | 改哪里 | 生效方式 |
|---|---|---|
| 流程拓扑（加/删/连节点） | 可视化编辑器改图 → 导出 `.ndjs` 覆盖 `Flow/*.ndjs` | 新节点建对应 `.py`，重启 |
| 节点业务逻辑 | 节点 `.py` 或 `services/` 封装 | 直接改，重启 |
| 节点参数/通道/窗格 | `Flow/pipeline.json` 或 SpecBuilder 代码 | 改完重启（无需重生成 ndjs） |
| 运行模式（线程/进程、混合） | `pipeline.json` 的 `run_mode` / 节点 `mode` | 改完重启 |
| 相机数/视频源 | 替换 `Flow/videos/` 下视频文件 + `pipeline.json` 的 `source` | 改完重启 |
| 框架能力 | `ProcessTest/HRFlowController.py` 源码 → Nuitka 编译 pyd | 见 README「发布流程」 |

## 8. 一句话总结

```
编辑器导出"图"（.ndjs 加密拓扑，随仓库提交）→ 节点 .py 提供"肉"（业务代码）
→ HRStar.py 交给框架解密按图驱动 → pipeline.json 声明"实例"（谁跑什么/连哪/显示哪）
```
